# はじめに：ハードウェア開発は「地球のカレンダー」に合わせる

前回の第1話では、オープンソースハードウェアの聖地である米国のクラウドファンディング「Crowd Supply」に、なぜ申請「前」の準備段階から挑戦ログを書き始めたのか、その背景や思いについてお話ししました。
さて、第2話となる今回のテーマは**「スケジュール計画」**です。プロダクト開発のスケジュールというと、「回路設計に◯ヶ月、ファームウェア開発に◯ヶ月……」といった**開発側の都合**から積み上げて計画してしまいがちです。しかし、日本にいながら海外の工場で製造し、世界中のユーザーへプロダクトを届ける場合、それだけではうまくいかないケースが少なくありません。ものづくりのタイムラインは、**「西の中国（製造サプライチェーン）」と「東のアメリカ（市場・顧客）」のそれぞれが持つ、特有のカレンダー事情（季節のイベントや商習慣）**に大きく左右されるからです。

今回は、アメリカと中国の季節要因を紐解きながら、なぜ「春ローンチ」を目指したほうがよさそうなのか、そこから逆算するスケジューリングの考え方について整理してみます。

---

# 1. 押さえておきたい「アメリカと中国」の特別なシーズン

世界を相手にしたハードウェア開発を進めるうえで、避けて通れないのが「中国とアメリカの年間カレンダー」です。

```
【西：中国（製造・調達）】              【東：アメリカ（市場・顧客）】
・1月〜2月：春節（工場が完全停止）      ・3月〜5月：タックスリターン（個人の財布が潤う）
・9月〜10月：ホリデー向け製造で繁忙期   ・11月〜12月：年末商戦（大企業の広告合戦）
```

それぞれの地域には、日本国内とはまったく異なる強烈な季節要因が存在します。

### ① 中国の事情（サプライチェーン側）
ハードウェアの試作や量産で広く活用されている基板製造・実装サービス（JLCPCB等）の多くは、中国（主に深圳周辺）に拠点を置いています。ここで特に意識しておきたいのが以下の2つの時期です。
* **春節（旧正月：1月下旬〜2月中旬頃）**：中国最大の祝日であり、多くの労働者が一斉に帰省します。工場はもちろん、前後の物流や部品調達も含めて約3週間〜1ヶ月近く機能がストップするため、「物理的なモノが動かない期間」として計算に入れておく必要があります。
* **秋の繁忙期（9月〜10月頃）**：世界中のクリスマス商戦に向けた製品の製造が集中するため、工場の製造ラインが混み合い、部品の納期遅延などが起きやすくなります。

### ② アメリカの事情（市場・顧客側）
一方、Crowd Supplyの拠点であり、メインのユーザー層が暮らすアメリカにも特有の経済サイクルが存在します。
* **タックスリターン（税金の還付：3月〜5月頃）**：アメリカでは春に確定申告が行われ、多くの国民に税金の還付金が支払われます。個人にとって臨時ボーナスのような時期であり、エンジニアやギークが趣味の電子工作ツールや新しいガジェット、クラウドファンディングへの支援にお金を使いやすくなる季節と言われています。
* **ホリデーシーズン・年末商戦（11月〜12月）**：ブラックフライデーやクリスマスなど消費が年間で最も盛り上がる時期ですが、同時に大手企業が巨額の広告費を投じて激しいプロモーション合戦を繰り広げます。個人や少人数のニッチなハードウェアは、この巨大な情報の波に埋没してしまいがちです。

# 2. 春の「PLAN A」vs 秋の「PLAN B」：なぜ春ローンチがよさそうなのか？

こうした地球規模のカレンダーを踏まえると、クラウドファンディングの公開時期は、大きく分けて**「春（4月中旬〜5月）」**と**「秋（9月〜10月）」**の2つの選択肢が考えられます。
「製品の完成度をじっくり高めたい」と考えると、時間を多く取れる秋ローンチ（PLAN B）を選びたくなります。しかし、市場環境と製造環境を俯瞰してみると、**春ローンチ（PLAN A）を目指したほうが好条件が揃いやすい**と考えられます。

| 比較項目 | **PLAN A：春ローンチ（4月中旬〜5月）** | **PLAN B：秋ローンチ（9月〜10月）** |
| :--- | :--- | :--- |
| **ユーザーの状況** | **◎ 支援が集まりやすい**<br>タックスリターンで個人の懐が温かい。 | **△ やや慎重になりやすい**<br>年末のホリデー出費を控え、買い控えが起きやすい。 |
| **マーケティング環境** | **◯ コミュニティに届きやすい**<br>大企業の広告ラッシュが落ち着き、自然に話題にしてもらいやすい。 | **× 情報戦に埋もれやすい**<br>大企業のブラックフライデー広告のノイズに埋没するリスクがある。 |
| **終了後の量産・出荷** | **◯ 工場が安定して動く**<br>初夏〜夏にかけての製造は工場の稼働が比較的安定している。 | **× 年末繁忙期・春節と衝突**<br>資金調達直後の年末ラッシュや翌年1〜2月の春節で、製造・発送が長期停止しやすい。 |

もちろん、未来のことは誰にも予見できません。開発が計画通りに進む保証はありませんし、予期せぬトラブルで遅延することもあるでしょう。そのため、バックアッププランとして「秋ローンチ（PLAN B）」の選択肢を持っておくことはリスク管理として大切です。
ただ、「完成度を上げるために最初から秋を目指す」としてしまうと、大企業の広告合戦に巻き込まれたり、調達後の量産が春節に直撃したりといった別のハードルを背負いやすくなります。そのため、まずは**「好条件が重なりやすい春ローンチ（PLAN A）を本命に据えておくのがよさそうだ」**という判断になります。

---

# 3. PLAN Aから逆算するタイムライン

では、仮に「4月中旬〜5月に本番ローンチする」と設定した場合、そこから逆算するとどのようなペース配分が求められるのでしょうか。逆算してみると、おおむね以下のようなタイムラインが見えてきます。

```
【4月中旬〜5月】 本番ローンチ（クラウドファンディング開始）
       ▲
【3月〜4月上旬】 プレローンチ（Coming Soonページ公開・事前登録の受付）
       ▲
【2月】          プラットフォーム担当者との条件協議・ページ構築
       ▲
【1月中旬】      Crowd Supplyへ正式申請（Submit） ※デモ動画・実機写真が必要
       ▲
【12月】         プロモーション動画（PV）撮影・コンテンツ制作
       ▲
【10月〜11月】   届いた基板の動作検証・デバッグ
       ▲
【9月中旬〜下旬】★ プレ製品版の設計・基板発注
```

春ローンチを成立させるためのポイントは、**「1月中旬の申請」**にあります。Crowd Supplyの審査を通過するためには、実際に動いている様子を収めたプロモーション動画が欠かせません。1月中旬に申請するためには、年内の12月には動画を撮影しておく必要があり、そのためには**12月の時点で「映像の中で確実に動く実機（プロトタイプ）」が手元になければなりません。**
そして、届いた基板をデバッグして動く状態に仕上げる期間を考えると、**「9月中には最初の基板設計を終えて工場へ発注しておかないと間に合わない」**という計算になります。

# おわりに

もちろん、計画はあくまで現時点での見立てに過ぎず、実際に進めてみれば予期せぬ問題や修正は次々と発生するはずです。それでも、地球規模のカレンダーをもとに一度逆算してみることで、「いつまでに、最低限どんな状態を作っておくべきか」という目安を持つことができます。

現在、まずはこの春ローンチのスケジュールを念頭に置きながら、プレ製品版となる「ADX CORE-S」の基板設計を進めている真っ最中です。試行錯誤を重ねながら、一歩ずつ形にしていければと思います。
